## Expansion transition boundary

All production Equation progress refresh callers now supply their immutable
Activity pre-state alongside the proposed final Equation and Blessing holdings.
One pure planner computes the final recipe counts, expansion set and Blessing
identity snapshot, then compares the prior expansion set with the final set:

- `newly_expanded` contains absent/unexpanded-to-expanded identities.
- `no_longer_expanded` contains expanded identities removed or no longer satisfied.
- Both lists use stable Equation identity order. Blessing enhancement without an
  identity change produces no new edge; a collapsed Equation can expand again.
- Unknown prior expansion identities reject planning instead of being erased.

The explicit accepted refresh result exposes these two lists. Inventory callers
lower progress operations, while the separately authored reward executor consumes
expansion edges once for the final batch and at each bounded reward step.
Progress planning itself does not consume RNG, write state or
authorize a command. The originating Activity transaction authenticates the
pre-state and commits ownership and progress together. Repeating a plan against
the same pre-state returns the same prospective edges, not another accepted
trigger. A caller composing cumulative rewards must lower its final inputs once
or explicitly track intermediate transitions; this planner does not deduplicate
independently appended plans.

Tests cover all 80 current recipes, level-only changes, removal, collapse and
re-expansion, acquisition with an already satisfied recipe, stale/unchanged
refresh rejection, and rollback after simulated downstream random work fails.
That simulated work is not itself a Curio reward. The separate
[9074 executor](divergent-universe-equation-expansion.md) now consumes these
edges in owning inventory transactions, including bounded reward-induced
cascades. This does not terminalize the full source-program obligation.

## Scope, ordering and rejection

Run-scoped slot 59 maps the active logical Node address to the last visit sequence
that received this reward. The existing shared logical-scope runtime supplies
both values. Physical battle/reward transitions that retain the same logical
Domain cannot replenish the budget. A new logical Domain or new visit can;
finalization clears the receipt. This describes the current logical topology,
not verified membership of every physical game room.

The owning command validates the offered/new Equation first. Equation insertion,
Blessing grants, final Equation progress, once receipt and offer consumption
commit together. Late validation or receipt-capacity failure restores the
Equation, Blessings, offer, events and RNG. Discard does not trigger this reward.
Other Blessing acquisition/Equation expansion effects remain separate work.

Production fixtures cover acquire/replace, active/destroyed/repaired states,
same-Domain physical transitions, next-Domain budgets, remaining deficits,
empty triggers, late rollback and deterministic vertical-slice reconstruction.
Neither a table row nor these focused fixtures terminalizes the outstanding
source-program audit in the [complete runtime goal](goals/22-divergent-universe-runtime.md).
