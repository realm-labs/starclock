# Offered Equation overwrite at fixed Respite

## Current executable boundary

`CompiledRespiteRoom::with_equation_reforge(policy, slots)` adds an optional
public service to an explicitly admitted fixed Respite. The configured current
Workbench must contain function 3 (102–105 or 110, not 101). This does not prove
original room/NPC admission. The caller supplies the accepted overwrite's
checked increasing Fragment price and an explicit room attempt limit of 1–64.

All commands use the exact whole-profile bound `choose_respite_service_option`
capability. The existing baseline runner dispatches its Service offers through
that capability; Activity, command processing, graph execution and RNG are not
forked. Raw graph commands cannot satisfy the physical-node transaction gate.

## Explicit replaceable selection and limit policy

Accuracy is
`VersionedProjectPolicyCurrentSameQualityUniformThreeMandatoryConfirmationExplicitRoomLimit`.

- Four enhancement pages expose the Equation service when affordable, below
  its caller-selected limit, with clean Equation progress, no unrelated pending
  Equation/Blessing offer and an eligible owned input.
- One input menu covers all 80 current Equation identities. The input must be
  owned and have a different unowned identity in its production quality category.
  All current unowned identities in that category, sorted by stable state key,
  form the explicit project-policy pool. This is not proof of original selector
  membership. No candidate is selected through an ID-range or name heuristic.
- Input selection checks state and price before sampling up to three uniform
  candidates without replacement on the shared Reward stream, purpose 22558.
  A one/two-member pool exposes all its members; an empty pool exposes no input
  action and consumes no RNG. Sampling caches the input and candidates without
  paying or incrementing successful overwrite counts.
- A sampled offer requires confirmation; no cancel, Leave or free reroll is
  offered at this intermediate boundary. These timing rules are explicit policy,
  not observed original cancellation/payment parity. Confirmation revalidates
  the entire cached set, input ownership, category, active Workbench and funds.
- Confirmation uses the existing accepted Equation replacement's state-only
  plan inside one shared generated-choice transaction: replace identity, tear
  down/recompute derived progress and expansion, debit Fragments, increment the
  independent Run-wide function-3 receipt and logical-room completion count,
  execute existing acquisition/expansion Curio rewards, clear the private offer
  and publish the next input menu. Failure rolls back this command's operations,
  events and draws while retaining the earlier committed sampling boundary.
- Exhausted funds, pool or attempt limit leaves only Back/Leave. The greatest
  safe linear-price count is tested before multiply/add, so next-price overflow
  cannot fault the menu or remove Leave. Input visits (415), navigation edges
  (414) and the caller-selected output/confirmation limit are finite compiler
  resource policies. Redundant navigation may exhaust a graph budget and reject;
  Leave has its own edge.

## State, composition and identity

Reuse the generic `respite_room::reforge::RespiteReforgeSlots` layout: input,
three-entry candidate map and completion count use logical Node scope; the
accepted marker resets at physical Node scope. Four addresses must be distinct,
at least 70, and disjoint from all other service addresses. Include the complete
`slot_definitions()` in the immutable whole definition before binding. Changed
declarations/programs or a foreign/unbound capability reject.

Equation overwrite composes with enhancement alone (eight physical nodes) or
with Blessing overwrite in either attachment order (thirteen nodes, eight
private service slots). Internal menus share the original single logical room;
they do not repeat Curio entry or initialize Heat. Both overwrite functions
have independent Fragment receipts and room counters. Enhancement uses Heat.
The original automatic exit clears Heat/Workbench and logical-room private
state resets at exit. No healing is added.

The profile payload binds the room's `configuration_digest()`: exact source
placement/catalog joins, prices, limit, addresses and actual input/output node
addresses, including attachment order. No production configuration row changed;
these are explicit host inputs. Static configuration promotion still requires
the production Excel/openpyxl/Sora path and provenance-bearing rows.
