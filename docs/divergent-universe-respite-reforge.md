# Offered Blessing overwrite at fixed Respite

## Current executable boundary

`CompiledRespiteRoom::with_blessing_reforge(group, price, slots)` adds an optional
public offered service alongside the existing enhancement menus. The current
Workbench must contain function 2. The caller chooses an existing closed
Blessing group, an increasing price policy and four disjoint slot addresses.
No unknown group, empty base-identity group, repeated attachment or reserved/
duplicate slot address is admitted. This is explicit host configuration, not
source NPC placement or proof of the original Workbench output selector.

All public commands use `choose_respite_service_option` on the exact bound
whole-profile capability. The baseline runner dispatches these Service offers
through the same capability. No shared engine, RNG, controller or command
processor is forked. Raw graph choices are not this mode executor: the input
and confirmation programs require its physical-node transaction gate.

## Explicit replaceable selection policy

Accuracy is
`VersionedProjectPolicyExplicitClosedGroupUniformThreeMandatoryConfirmation`.

- The selected current Sora group supplies its base-level identity members;
  current enhanced-level members are not treated as additional identities.
  The pool is sorted by stable state key. It is a caller-selected policy pool,
  not a recovered Workbench selector or original weight table.
- Enhancement pages offer an entry to four input pages. Every currently owned
  catalog identity, including enhanced inputs, is eligible as input. Input
  selection checks clean Equation progress, no unrelated Blessing offer,
  Workbench identity, affordability, room budget and at least one unowned pool
  identity before drawing. The input pages cover all 414 identities without
  exceeding the shared 256-option limit.
- Input selection samples three unowned pool identities uniformly without
  replacement on Reward RNG, or all remaining identities for a one/two-member
  pool. Empty pools do not draw and expose no new input command. Candidates and
  selected input persist in logical-room scoped state; page returns do not
  redraw, reset Heat or run another Curio domain entry.
- A sampled offer requires confirmation. No cancel/free reroll or Leave is
  offered at that intermediate decision. This deliberately explicit timing
  policy avoids inventing free candidate fishing; original cancellation and
  payment timing remain unproven. Leave is available before sampling and after
  confirmation. Confirmation rechecks the entire cached candidate set, input,
  current price and funds. It uses the existing accepted rewrite's state-only
  plan inside the shared generated-option transaction, not a second mutation.
- Confirmation atomically replaces the input with the selected base identity,
  debits Fragments, increments the Run-wide function-2 receipt and room count,
  refreshes Equation progress and grants any current expansion rewards. It
  clears the pending input/candidates and returns to the first input page.
  Failure preserves the already committed sampling command, pending offer and
  its RNG state; confirmation's own operations/draws are rolled back.
- The compiler budget is 64 confirmations per logical room. Input pages have
  415 visits and navigation edges 414 traversals; enhancement pages gain 64
  additional visits to accommodate service returns. The output node permits
  64 visits. These are explicit finite compiler resource policies, not original
  service caps. Redundant navigation can exhaust its budget and reject through
  the mode transaction; the dedicated Leave edge remains separate.
- When funds, pool or confirmation budget are exhausted, input pages expose
  only Back/Leave, not navigation-only loops. Price affordability first checks
  the largest safe overwrite count before evaluating its multiply/add, so a
  next-price overflow cannot fault the menu or remove Leave.

The numeric policy remains
`VersionedProjectPolicyAcceptedBlessingReforgeLinearRunPrice`: positive checked
base/increment, Fragment currency and Run-wide successful overwrite count.
Exact prices, discounts, free-attempt Curios and their limits are still pending.
No numeric parity is claimed. See the [accepted settlement contract](divergent-universe-workbench-reforge.md).

Reject-all behavior and a flat/free replacement are rejected alternatives;
neither supplies the known selectable overwrite shape and increasing-cost
constraint. Reusing an old mode's weights, candidate membership or prices is
also rejected. Confidence in original selection/weight/timing parity is absent.
Replace this host policy when current released evidence supplies NPC admission,
output pool/weights, cancellation/payment timing and per-Workbench limits.

## State and composition

Selected input, bounded candidate map (three entries) and completion count use
the existing logical Node scope. The accepted marker uses physical Node reset.
The four host addresses must be at least 70 and mutually distinct; whole-profile
construction separately rejects collisions with other caller-owned slots.
Include `slot_definitions()` before building the shared immutable definition.
Room validation requires these exact declarations and all added graph programs.

All eleven physical nodes retain the original room's single logical scope.
The single entry retains the Curio lifecycle prefix and Heat initialization;
the four enhancement pages, four input pages, candidate output and automatic
exit never count as additional domains. Enhancement and overwrite share one
configured Workbench but retain independent Heat/Fragment payment semantics.
The existing automatic exit clears Heat/Workbench before the next source
position. Leaving the logical room resets its private overwrite state.

The profile payload includes the room's `configuration_digest()`, now binding
the selected group, stable candidate keys, price digest, host slots and budget
as well as source placement and current source/decision catalogs. No workbook
or generated data is edited: these are explicit host-profile inputs. Static
production selectors/prices still require Excel/openpyxl/Sora promotion.
