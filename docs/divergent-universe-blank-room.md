## Headless execution

`blank_room_compiler().compile(context)` checks the exact current position join,
fixed Blank composition, preset and level. `compile_curio_domain_route` wraps
the single entry with the existing production Curio lifetime/income operations.
Internal movement to the waiting menu never repeats those entry operations.

The room grants no intrinsic currency, Blessing, Equation, Curio, service receipt
or reward RNG draw. At the menu it records completion, then opens doors, then
offers one independent Leave. The flags use the exact current physical-node
reset declarations. Leaving advances to the source compiler's exact successor;
it does not skip a position or mark the whole guide/run complete.

Timing accuracy is
`VersionedProjectPolicyEmptyPayloadImmediateCompletionIndependentLeave`:

- Missing fact: the original empty-room completion/door timing and any
  presentation acknowledgment.
- Selected policy: normal entry lifecycle, immediate completion followed by
  door publication at the waiting boundary, then a separate accepted Leave.
- Alternatives: auto-traversal would hide the room boundary; waiting for an
  invented challenge/result would introduce unsupported room-local content.
- Rationale: a headless empty domain must retain its entry semantics and an
  observable exit without fabricating rewards or presentation work.
- Confidence: high in the no-local-payload fact and deterministic invariants;
  original timing is unverified, not observed parity.
- Replacement: released executable room tasks or reproducible current-version
  observations establish a different completion or exit gate. Replace that
  timing policy while preserving transaction atomicity and entry-once behavior.

`bind(definition)` requires exact room programs, entry/exit edges, logical
Run/Plane/Node addresses, production flag declarations and Curio entry lowering.
Room-local random offers, checkpoints, interaction bindings and entry bypasses
reject. The capability authenticates the whole immutable definition during
observation and Leave. The owner must bind the room configuration digest and
all other immutable profile inputs before starting the Activity.

Leave uses the existing shared generated-option transaction. Stale, unknown,
foreign or consumed decisions and downstream entry errors preserve authoritative
bytes, hashes, debug events, pending offers and RNG. No native no-op handler,
second state machine or direct live-state write is introduced.

## Verification and remaining integration

```text
cargo test -p starclock-mode-universe blank_room
```

Tests compile the real guide positions with all nine authored decks, execute
the actual Blank fragment, compare fresh factories, check finish-before-door
events and physical resets, and reject changed programs, flag policies and
logical scopes. Curio 9071's production entry income remains 60 fragments and
its allowance decreases from three to two exactly once; Leave does not repeat
it. A failing successor leaves the completed room and its pending exit intact.

Other guide-room payloads in these tests remain explicit probes. This is a
production room compiler/capability, not a complete playable guide, default
Ordinary/Cyclical profile integration, encoded profile replay or terminal source
coverage. Those release requirements and all current denominators remain intact.
