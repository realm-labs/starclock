# Divergent Universe initial Equation choice

## Current executable boundary

Both production baseline families begin with a required public `Preparation`
choice. The `InitialEquations` workbook table selects three distinct current
Epic-category identities with uniform integer weights on the shared Reward RNG,
purpose 23801. Exactly one selected identity is acquired before the existing
initial event. All current reference identities remain stable; category membership
does not become evidence of original pool membership.

The selection uses the shared random-offer implementation and generated-choice
transaction. The public offer authenticates the option before the generator
inserts ownership, refreshes Equation progress and applies acquisition grants.
Node-scoped slot 60 guards the authored traversal: a raw graph choice cannot
bypass acquisition. An unconsumed internal Equation offer rejects the accepted
reward instead of being overwritten. Stale, hidden, duplicate or late-failing
commands preserve state, pending choices and RNG together.

The added physical node shares logical Run/Plane/Node 1 with the initial event,
battle and battle reward. Crossing these physical boundaries does not refresh
Trailblaze Wax's logical-Domain grant budget. The default baseline now has ten
accepted actions and three actual layer battles; this is not a complete run
topology. CLI, Agent and MCP use the same baseline runner and replay transcript.

## Provenance and accuracy

Decision source 17 binds `ExcelOutput/RogueTournFormula.json` at released 4.4
revision `fd978d6ef09f941fba644c731ab54abd6f7c3568` of
[Dimbreath/turnbasedgamedata](https://gitlab.com/Dimbreath/turnbasedgamedata).
The inspected file SHA-256 is
`87778b3d411554657e9609d2e364395bcbc55ba38f8b15e1d250e475e81f2598`;
review date is 2026-09-09. It proves identity/category records, not initial
placement, width, weights, rarity-to-star mapping or pool membership. Released
RandomID records without members cannot supply that missing proof.

`VersionedProjectPolicyUniformCurrentCategorySingleSelection` explicitly owns
those missing fields. It applies the same choice before the baseline event to
Ordinary and Cyclical entries, uses Epic-category candidates and unit weights,
permits no reroll and accepts exactly one. Confidence in these individual fields
is low. Alternatives include entry-specific fixed pools, weighted Path selection,
other categories and selection after entry-specific boons. Replace each field
independently when released current-profile execution data or reproducible
observations establish it.

A [public Arcadian Chronicles overview](https://honkai-star-rail.fandom.com/wiki/Divergent_Universe%3A_Arcadian_Chronicles/Extrapolation)
indexed on review describes an initial Equation choice as part of a larger
starting loadout. This is not sufficient to bind that iteration's full sequence
to the frozen profile here, and is not promoted to exact workbook provenance.
Missing mask/Titan selection, Great Blessings, initial Blessing batches and
room-wide Equation reward placement remain gaps, not zero-effect policies.

## Verification

Production tests check both families, exact offered category and width,
deterministic reconstruction, raw-choice bypass rejection, hidden and duplicate
choices, all three selections followed by real battles and fresh replay,
competing internal offers, acquisition grants across the initial/event physical
boundary, and late receipt-capacity failure with full RNG rollback. Data tests reject invalid
widths, missing policy explanations and broken source references. The workbook
validator reconstructs the workbook with openpyxl and compares current Sora
schema locks, readers and binary/debug exports byte-for-byte.

This boundary does not terminalize the outstanding source-program audit in the
[complete runtime goal](goals/22-divergent-universe-runtime.md).
