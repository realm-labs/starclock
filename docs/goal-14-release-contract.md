# Goal 14 Release Contract

Goal 14 releases the Version 4.4 Gold and Gears Activity profile over the
immutable Goal 08 Candidate bundle and the released generic Activity/Battle
boundaries. Its immutable identity is `gold-and-gears-runtime-v1`.

## Released boundary

The release binds all 7,913 source obligations, 1,224 mechanic rules, 18
semantic fixture families and 16 inherited policy boundaries to exact-once
terminal runtime dispositions. The private 52-table, 29,140-row Sora bundle
lowers into immutable catalogs; production runtime paths read no normalized
JSON or workbooks and admit no native content handler.

The runtime executes the three-plane graph, Cognition and Secrets, Custom
Dice, Knowledge, Neural progression, independent Conundrum tracks, Path and
Resonance progression, content/services/Adventure outcomes and real nested
battles. Versioned project policies remain visibly non-parity where released
evidence does not expose engine enumeration or numeric values.

## Frozen evidence

The release binds:

- 25 valid seeded complete runs covering five difficulties, nine Paths,
  twelve Custom Dice, both Conundrum tracks from 0–6 and the 6+6 cap;
- 404 real nested battles with freshly reconstructed run verification;
- component-addressed replay plus baseline, CLI, agent and MCP offered-command
  parity over the same immutable runtime factory;
- separate Activity-command, Battle-command, event/state, replay and
  seven-domain RNG goldens, bounded malformed-input corpora and rollback;
- seven stable-runner performance workloads, including 10,000 allocation-free
  warm battle assemblies and 16 concurrent shared-catalog sessions; and
- dependency/license, architecture, native-handler, provenance, generated
  drift, source-cache, prior-release and fresh clean-checkout audits.

The machine-readable release is generated and checked with:

```text
node tools/goal14/verify-release-contract.mjs . --release
```

## Native and snapshot boundary

Windows x64, Linux x64 and macOS ARM64 execute the same Goal 14 hardening
goldens in hosted CI. The successful artifacts must bind the exact P8-B4
completion commit; Windows ARM64, Linux ARM64 and macOS x64 remain compile-only
and make no runtime claim.

The P8-B4 completion commit is registered separately in
`policy/release-snapshots.json` only after those three hosted jobs succeed.
The registration commit retains their receipts in
may evolve current source, but it may not rewrite the frozen completion tree.

## Accuracy boundary

The release claims deterministic execution of the frozen released facts and
explicit versioned policies. Synthetic matrix rosters and documented enemy or
policy fallbacks do not claim observed balance, hidden-weight or unpublished
engine parity. Story presentation, account rewards, achievements and assets
remain outside the released runtime boundary.
