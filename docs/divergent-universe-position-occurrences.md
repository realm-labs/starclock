# Explicit Divergent Universe source-position events

## Current boundary

The production factory supplies `occurrence_room_compiler(variant)` for an
explicitly selected, executable authored event. It reuses the existing
[occurrence choices and rewards](divergent-universe-occurrence-rewards.md),
availability conditions, costs, acquisition operations and labeled Reward RNG.
Unknown/reference-only variants reject; no generic event or empty completion
handler is substituted. Current authored choices remain the replaceable
200-fragment / two-Curio / two-Blessing policy, not recovered original NPC code.

Explicit placement, including repeated placements, is a low-confidence project
orchestration policy, not observed original event membership or repeatability.
The missing fact is released event admission at each source position. Requiring
the owner to select the variant avoids inventing a random pool from reference
identities. Replace that selection independently when released selectors or
reproducible observations establish membership. Original event programs,
unimplemented acquisition effects and complete-run release gates remain pending.
No reference obligation or mechanic becomes terminal through this composition.

## Explicit same-room sequences

`compile_sequence(context, following)` composes the first selected variant and
zero through two following executable variants in caller order. Repeats remain
distinct checkpoints; unknown variants and more than three total events reject.
An empty following list has the same graph and identity as `compile(context)`.
Sequence identity binds every ordered variant, physical node and continuation
policy. Whole-definition binding also checks intermediate programs and scopes.
This primitive does not validate a source level's event count or select a pool;
current-profile admission must establish those facts separately.

The one logical room has one lifecycle entry. Each accepted event commits its
own reward and dialogue/predicate/content-updated flags. Intermediate events
leave room completion and doors false, then offer a separately accepted Continue
guarded by those three flags. Continue initializes the next checkpoint without
repeating Curio income or domain allowances. Only the final reward finishes the
room and publishes a door-gated Leave. A rejected reward or Continue restores
that command's state, events and RNG, preserving earlier committed rewards.

## Immutable profile contract

Compile a plain mapped `with_runtime_battle_route` entry, then reuse the event
compiler across independently selected source-position contexts. Each compiled
room contributes single-visit entry and event Choice nodes in its bounded namespace.
The entry's automatic transition keeps lifecycle branches small instead of
duplicating the full event program. Both nodes share one logical room.
Supply its raw `fragment()` to `compile_curio_domain_route`; the exact lifecycle
prefix is required before the capability can bind. Entry income and domain
allowances execute once on accepted room entry, not on reward selection or Leave.

Use `position_room_identity_with_occurrences` and
`bind_position_rooms_with_occurrences` with the same exact battle, Tawot and
event lists. They retain the [whole-profile contract](divergent-universe-position-battles.md):
base participants/state, exact source joins, graph, programs and logical scopes
are validated before creating an immutable flow. The identity binds current
source/decision digests and each event's variant and exact placement in stable
entry-node order. Cross-kind and repeated entry bindings reject. The owner's
payload still binds the deck, hand width, remaining programs and policy inputs;
it is not a placeholder configuration identity.

Event binding rejects changed or omitted lifecycle-prefixed programs, altered
nodes, bypass exits, extra room random policies, interactions and wrong
Run/Plane/Room paths. Commands authenticate the complete immutable definition,
including separately reconstructed definitions, before reward generation.
An already-running Activity is never rebound.

## Accepted commands and rollback

Entry initializes the authored dialogue key, reward guard and completion flags,
then offers only available authored choices. `offered_occurrence` observes the
current bound event. `choose_occurrence_option` rechecks the actual offer,
state hash, variant key and eligibility before drawing RNG. The existing
headless controller dispatches the choice through this executor.

One shared generated-option transaction commits costs, sampled rewards and
reviewed acquisition operations before headless dialogue completion, room
completion and door publication. Ordinary raw option selection cannot bypass
the accepted-reward guard. Hidden, stale, foreign, repeated, overflow and late
content rejections leave canonical state and RNG unchanged.

The next offer is a door-gated Route choice at the same physical node. Leave
is a separate accepted command; it does not rerun entry lifetimes. Failing a
later room entry restores that command's deck, scopes and RNG, but cannot undo
an event reward already committed by an earlier accepted command. Moving to
the next room resets its node-scoped dialogue/completion state.

Both families' controlled fixtures execute actual proxy battles followed by all
three event rewards, compare fresh command reconstruction, and complete repeated
event visits through the existing controller. Other rooms are explicit probes;
placement does not interpret a card's kind as event admission. Default
CLI/Agent/MCP gameplay remains the three-battle proxy. These tests are not
complete source-position gameplay, encoded-profile replay or full-run evidence.
